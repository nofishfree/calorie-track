## 二、用户认证模块

### 2.1 前端数据结构

#### User (前端类型)
```typescript
interface User {
  id: string            // UUID，由后端生成
  email: string
  username?: string
  avatar?: string
  data_version?: number // 数据版本号，用于增量同步
}
```

#### AuthState (认证状态)
```typescript
interface AuthState {
  user: User | null           // 当前登录用户
  token: string | null        // JWT Token
  isLoggedIn: boolean         // 登录状态
  isLocalAccount: boolean     // 是否为本地账号（跳过服务器请求）
  savedAccounts: SavedAccount[] // 已保存的账号列表
  currentAccountId: string | null // 当前账号 ID
}
```

**本地账号特殊 ID**: `'local-account'`

#### SavedAccount (已保存账号)
```typescript
interface SavedAccount {
  token: string
  user: User
}
```

### 2.2 后端数据结构

#### UserResponse (用户响应)
```rust
pub struct UserResponse {
    pub id: Uuid,
    pub email: String,
    pub username: Option<String>,
    pub avatar: Option<String>,
    pub is_admin: bool,
    pub created_at: DateTime<Utc>,
    pub data_version: i64,  // = operation_logs 中该用户最大 serial_number
}
```

#### 数据库表: `users`
| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID (PK) | 主键 |
| email | VARCHAR(255) UNIQUE | 邮箱，唯一 |
| password_hash | VARCHAR(255) | BCrypt 密码哈希 |
| username | VARCHAR(100) | 用户名 |
| avatar_url | TEXT | 头像 URL |
| is_admin | BOOLEAN | 是否管理员，默认 false |
| created_at | TIMESTAMPTZ | 创建时间 |

### 2.3 API 端点

| 方法 | 端点 | 说明 | 认证 |
|------|------|------|------|
| POST | `/api/auth/register` | 用户注册 | 公开 |
| POST | `/api/auth/login` | 用户登录，返回 Token | 公开 |
| POST | `/api/auth/forgot-password` | 忘记密码 | 公开 |
| POST | `/api/auth/reset-password` | 重置密码 | 公开 |
| POST | `/api/auth/change-password` | 修改密码 | 需认证 |
| GET | `/api/user/me` | 获取当前用户信息 | 需认证 |
| PUT | `/api/user/me` | 更新用户资料 (username, avatar) | 需认证 |
| DELETE | `/api/user/me` | 删除账号 | 需认证 |

### 2.4 数据流向

```
登录流程:
  用户提交 email + password
    → POST /api/auth/login
    → 后端验证 (email + bcrypt 密码匹配)
    → 返回 { token, user }
    → 前端存储 token + user 到 authStore (localStorage 持久化)
    → 启动轮询同步 (startPolling)

自动登录:
  App.tsx → AutoLogin 组件
    → 从 localStorage 读取 auth-storage
    → 调用 login(token, user) 恢复状态
    → 若为远程账号则启动轮询

登出流程:
  logout()
    → 调用 stopPolling() 停止同步
    → 清除 token，切换到 local-account
    → 从 savedAccounts 中移除当前账号
```

## 三、食物 (Food) 模块

### 3.1 前端数据结构

#### Food (前端类型 — 完整结构)
```typescript
interface Food {
  id: string              // UUID，前端生成
  name: string            // 食物名称
  num: number             // 每份量基准数量（如 100g）
  calorie: number         // 每份量热量
  calorie_unit: 'kcal' | 'kj'  // 热量单位
  carbs_g: number         // 每份量碳水（克）
  protein_g: number       // 每份量蛋白质（克）
  fat_g: number           // 每份量脂肪（克）
  unit: string            // 份量单位（如 'g', 'ml', '个'）
  user_id?: string        // 所属用户 ID（可选，系统食物为 undefined）
}
```

#### ServerFood (服务器食物响应)
```typescript
interface ServerFood {
  id: string
  user_id: string | null   // 服务器返回 null 表示系统食物
  name: string
  num: number
  calorie: number
  calorie_unit: string
  carbs_g: number
  protein_g: number
  fat_g: number
  unit: string
  usage_count?: number | null
}
```

**映射关系**: `ServerFood.user_id (string | null)` → `Food.user_id (string | undefined)`

#### FoodState (食物状态)
```typescript
interface FoodState {
  foods: Food[]                              // 所有食物（系统 + 用户自定义）
  foodUsageCounts: Record<string, number>    // 食物使用次数，key: `${foodId}:${userId}`
  lastUsedServings: Record<string, number>   // 上次使用份量，key: `${foodId}:${userId}`
  savedFoodIds: Record<string, string[]>     // 各账号保存的食物 ID 列表
  newlyCreatedFoodIds: string[]              // 新创建的食物 ID（未持久化）
  modifiedFoodIds: string[]                  // 已修改的食物 ID
}
```

#### 数据库表: `foods`
| 字段 | 类型 | 说明 |
|------|------|------|

| calorie | DOUBLE PRECISION | 热量 |

### 3.3 API 端点

| 方法 | 端点 | 说明 |
|------|------|------|
| GET | `/api/foods` | 获取食物列表（支持搜索、分页） |
| POST | `/api/foods` | 创建食物（需客户端提供 ID） |
| GET | `/api/foods/:id` | 获取单个食物 |
| PUT | `/api/foods/:id` | 更新食物（只能更新自己的） |
| DELETE | `/api/foods/:id` | 删除食物（只能删除自己的） |

### 3.4 数据流向

```
创建食物:
  用户填写表单 → generateUUID() 生成 ID
    → foodsAPI.createFood({ id, name, ... })
    → 后端验证 ID 格式 → 插入 foods 表 → 记录操作日志
    → 前端: foodStore.addFood(food)
      → 更新 foods[] 列表
      → 调用 operationStore.addOperation('food', food.id, data)
        → 操作进入待同步队列

更新食物（跨用户）:
  若原食物属于其他用户 → 生成新 ID → 作为新食物添加
  若属于当前用户 → 原地更新 → 添加 'update' 操作到队列

加载食物列表:
  登录后 → foodsAPI.getFoods()
    → 返回 ServerFood[] → 映射为 Food[]
    → foodStore.setFoods(foods) 覆盖本地数据
    → 本地操作队列优先于服务器数据
```

## 四、饮食记录 (MealRecord) 模块

### 4.1 前端数据结构

#### MealRecord (前端类型)
```typescript
interface MealRecord {
  id: string                          // UUID
  user_id: string                     // 记录所属用户
  food: Food                          // 完整食物快照（嵌入）
  serving_count: number                // 实际使用份量
  record_time: string                 // ISO 8601 格式时间
  calories_total: number              // 总热量
  carbs_total: number                 // 总碳水
  protein_total: number               // 总蛋白质
  fat_total: number                   // 总脂肪
  plan_id?: string                    // 关联套餐 ID
  plan_name?: string                  // 关联套餐名称
  plan_items?: Array<{                // 套餐详情快照
    food_id: string
    food: Food
    quantity: number
  }>
  is_quick_add?: boolean              // 是否快捷添加
}
```

#### RecordState (记录状态)
```typescript
interface RecordState {
  records: MealRecord[]
  addRecord: (record) => void        // 添加记录 + 入队 + IndexedDB
  updateRecord: (id, record) => void  // 更新记录 + 入队
  deleteRecord: (id) => void          // 删除记录 + 入队
  setRecords: (records) => void       // 批量设置（服务器同步）
  setRecordsForDate: (date, records) => void  // 按日期覆盖
  getRecordsByDate: (date, userId?) => MealRecord[]
  getDailyNutrition: (date) => { calories, protein, carbs, fat }
}
```

#### IndexedDB LocalRecord (离线存储)
```typescript
interface LocalRecord {
  local_id: string          // 本地 UUID
  user_id: string
  record_time: string       // ISO 8601
  food_name: string
  food_id?: string
  serving_size: number
  serving_unit: string
  calories: number
  protein_g: number
  fat_g: number
  carb_g: number
}
```

#### IndexedDB Store 方法 (recordStore.ts)
```typescript
// 添加记录（自动生成 local_id）
addRecord(record: Omit<LocalRecord, 'local_id'>): Promise<LocalRecord>

// 更新记录
updateRecord(localId: string, updates: Partial<LocalRecord>): Promise<void>

// 删除记录
deleteRecord(localId: string): Promise<void>

// 按日期查询（通过 by-user 索引 + 时间过滤）
getRecordsByDate(date: string, userId?: string): Promise<LocalRecord[]>

// 按用户查询所有记录
getRecordsByUserId(userId: string): Promise<LocalRecord[]>

// 按 local_id 查询
getRecordByLocalId(localId: string): Promise<LocalRecord | undefined>

// 按用户删除所有记录
deleteRecordsByUserId(userId: string): Promise<void>

// 将匿名用户记录迁移到指定用户
migrateAnonymousRecords(toUserId: string): Promise<void>
```

**IndexedDB 数据库**: `CalorieTrackerDB` (v1)

| Store 名 | 主键路径 | 索引 |
|----------|---------|------|
| records | local_id | by-user (user_id), by-record-time (record_time) |
| foods | local_id | by-user (user_id) |
| goals | user_id | — |
| preferences | user_id | — |

### 4.4 数据流向

```
添加记录:
  用户选择食物 → 设置份量 → 计算营养
    → recordStore.addRecord({...})
      → 生成 UUID 作为记录 ID
      → records[] 新增记录（Zustand 内存）
      → operationStore.addOperation('record', id, data)  // 入同步队列
      → IndexedDB 异步保存 (queueMicrotask)
      → 版本化同步时通过 syncAPI 上传到服务器

每日营养统计:
  getDailyNutrition(date)
    → 过滤当天记录 → reduce 求和
    → 返回 { calories, protein, carbs, fat }

服务器加载记录:
  recordsAPI.getRecordsByDate(date)
    → 返回 ServerMealRecord[]
    → 前端映射为 MealRecord[]
    → recordStore.setRecordsForDate(date, records)
```

```

  用户填写名称 + 选择食物 + 设置份量

  getLocalPlanDetail(id)
    → 遍历 items，按 quantity/food.num 比例计算各营养成分总和
    → 生成 MealPlanDetail（含 items + 汇总数据）
```

### 6.4 数据流向

```
循环目标日期更新:
  checkAndUpdateDate()
    → 比较 last_active_date 与今日
    → 计算 dayDiff = today - lastActiveDate
    → newIndex = (today_index + dayDiff) % cycleDays
    → 更新 today_index 和 last_active_date

获取当前目标:
  getCurrentGoal()
    → 查找 currentTemplateId 对应的模板
    → 若为 cycle 类型 → 按 today_index 取 daily_goals[todayIndex]
    → 若为 daily 类型 → 取 daily_goals[0]
    → 返回扁平化的 UserGoals

服务器同步:
  goalTemplatesAPI.getAll()
    → 返回 ServerGoalTemplate[]
    → goalStore.syncTemplates(templates, currentId)
    → 若 ID 格式不兼容（旧版本地短 ID）→ 回退为 POST 创建新模板
```

## 七、数据同步机制

### 7.1 同步架构总览

```
┌─────────────────────────────────────────────────────────────┐
│                     前端同步流程                              │
│                                                             │
│  用户操作 (add/update/delete)                               │
│       │                                                     │
│       ▼                                                     │
│  Store 方法调用 (如 foodStore.addFood)                      │
│       │                                                     │
│       ▼                                                     │
│  operationStore.addOperation()                              │
│  ┌──────────────────────────────────────┐                   │
│  │  Operation Queue (localStorage 持久化) │                   │
│  │  {                                   │                   │
│  │    [userId]: OperationItem[]          │                   │
│  │      - id                            │                   │
│  │      - operation_type: add|update|delete               │
│  │      - entity_type: food|record|plan|goal|account       │
│  │      - entity_id                     │                   │
│  │      - data: any                     │                   │
│  │      - created_at                    │                   │
│  │  }                                   │                   │
│  └──────────────┬───────────────────────┘                   │
│                 │ 每秒轮询 performSync()                     │
│                 ▼                                           │
│  syncAPI.versionedSync(request)                             │
│  ┌──────────────────────────────────────┐                   │
│  │  POST /api/sync/versioned             │                   │
│  │  请求: {                              │                   │
│  │    client_version: number,            │                   │
│  │    head_operation: SyncOperationReq  │                   │
│  │  }                                    │                   │
│  │  响应: {                              │                   │
│  │    server_version: number,            │                   │
│  │    operations: OperationLog[],        │                   │
│  │    head_processed: boolean            │                   │
│  │  }                                    │                   │
│  └──────────────┬───────────────────────┘                   │
│                 │                                           │
│  • head_processed=true → 移除队头操作                        │
│  • server_version > client_version → 更新 data_version       │
│  • operations 非空 → 增量数据应用到本地                       │
└─────────────────────────────────────────────────────────────┘
```

### 7.2 OperationItem (操作队列项)
```typescript
interface OperationItem {
  id: string                                    // 操作唯一 ID (随机生成)
  operation_type: 'add' | 'update' | 'delete'
  entity_type: 'food' | 'record' | 'plan' | 'goal' | 'account'
  entity_id: string                              // 实体 UUID
  data: any                                      // 实体完整数据
  created_at: string                             // ISO 8601
}
```

队列按用户 ID 分组存储: `Record<userId, OperationItem[]>`

### 7.3 同步请求/响应

#### VersionedSyncRequest (前端→后端)
```typescript
interface VersionedSyncRequest {
  client_version: number                // 客户端数据版本 (User.data_version)
  head_operation?: SyncOperationRequest | null  // 队头操作
}

interface SyncOperationRequest {
  operation_type: string
  entity_type: string
  entity_id: string
  data: Record<string, unknown>
}
```

#### VersionedSyncResponse (后端→前端)
```typescript
interface VersionedSyncResponse {
  server_version: number               // 服务器当前版本 (max serial_number)
  operations: OperationLog[]            // 增量操作日志
  head_processed: boolean               // 队头操作是否已处理
}

interface OperationLog {
  id: string
  user_id: string
  serial_number: number                // 操作序号（自增）
  operation_type: string
  entity_type: string
  entity_id: string
  data: Record<string, unknown>
  created_at: string
}
```

### 7.4 后端同步处理逻辑

```
versioned_sync():
  1. 获取服务器数据版本 (MAX(serial_number) FROM operation_logs)
  2. 处理队头操作:
     a. 查询 entity_id 是否已在 operation_logs 中
     b. 若不存在 → 加入内存操作队列 → process_operation_queue()
        → 执行实际数据库操作 → 记录操作日志
     c. 若已存在 → 标记 head_processed = true
  3. 若 server_version > client_version
     → 返回 serial_number > client_version 的增量操作日志
  4. 返回 VersionedSyncResponse

process_operation_queue():
  • 从内存队列取出所有操作
  • 逐个记录操作日志到 operation_logs 表
  • serial_number 自增，保证唯一
```

### 7.5 数据库表: `operation_logs`
| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID (PK) | 主键 |
| user_id | UUID (FK→users.id) | 用户 ID |
| serial_number | BIGINT | 序列号（版本号），与 user_id 联合唯一 |
| operation_type | VARCHAR(20) | 操作类型: add/update/delete |
| entity_type | VARCHAR(20) | 实体类型: food/record/plan/goal/account |
| entity_id | VARCHAR(64) | 实体 ID |
| data | JSONB | 操作数据快照 |
| created_at | TIMESTAMPTZ | 创建时间 |

### 7.6 各实体类型的同步上传映射

前端通过 `syncAPI.uploadOperation()` 根据 `entity_type` 路由到不同 API:

| entity_type | operation_type | API 端点 | 请求体 |
|-------------|---------------|---------|--------|
| food | add | POST `/api/foods` | CreateFoodRequest (含 id) |
| food | update | PUT `/api/foods/:id` | UpdateFoodRequest |
| food | delete | DELETE `/api/foods/:id` | — |
| record | add | POST `/api/records` | CreateMealRecordRequest |
| record | update | PUT `/api/records/:id` | UpdateMealRecordRequest |
| record | delete | DELETE `/api/records/:id` | — |
| plan | add | POST `/api/plans` | CreatePlanRequest |

| goal | add | POST `/api/goal-templates` | CreateGoalTemplateRequest |

### 7.7 同步触发时机

| 时机 | 触发方式 |
|------|---------|
| 登录成功后 | `startPolling()` 启动每秒轮询 |

| 登出时 | `stopPolling()` 停止轮询 |
| 后台运行 | 定时器 `setInterval` 每 1000ms 调用 `performSync()` |
